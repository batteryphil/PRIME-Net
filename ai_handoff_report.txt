1. ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
The PRIME Engine is a custom hybrid continuous/discrete symbolic regression 
optimizer. It abandons traditional Genetic Programming (crossover/mutation trees) 
in favor of a differentiable-like voting mechanism on a discrete token manifold.

Core Mechanics:
- RPN Sequential Evaluator: Equations are represented as fixed-length (SEQ_LEN=15) 
  Reverse Polish Notation integer arrays. A custom stack-based evaluator parses 
  these arrays to execute math (sin, exp, log, +, *, etc.).
- Continuous Rprop Steering: Random structural mutations are evaluated. Good 
  mutations (lower MSE) add positive votes to a floating-point `vote_buffer`.
- Sign-based Step Updates: When accumulated votes cross a threshold, the master 
  sequence deterministically steps (flips tokens) in that direction.
- MDL Occam's Razor: A structural complexity penalty (`lambda_penalty`) is 
  dynamically subtracted from fitness to prevent hallucination.

2. COMPUTATIONAL INFRASTRUCTURE & HARDWARE BLOCKERS
--------------------------------------------------------------------------------
*WARNING: DO NOT ATTEMPT TO USE PyTorch HIP OR NATIVE OPENCL FOR THIS ENGINE*

Initial Development:
- We successfully wrote a native OpenCL C kernel (`eval_population`) to parallelize
  2048 evaluations on the user's AMD RX9060 XT (gfx1200 / RDNA 4).
- Critical Blocker: The Mesa Rusticl / ROCm driver stack on Linux kernel 7.0.0-30

Current Solution (High-Performance CPU JIT):
- We transitioned to Numba (`@njit(parallel=True)`), compiling the exact C-like 
  RPN evaluator to optimized LLVM CPU machine code. 
- Performance is staggering: 2048 evaluations of N=1000 take ~1.6 milliseconds 
  (~5.0 seconds for 3000 generations), heavily outperforming the OpenCL GPU overhead.
- All future development should remain on the Numba CPU JIT (`run_prime_numba`).

# SECTION 6: FINAL HARDENING (CLOSING THE OCCAM LOOPHOLE)

While the Topological Crossover enabled rapid composition, early testing revealed a critical 
flaw in the scoring mechanism: the linear Minimum Description Length (MDL) penalty was 
insufficient to prevent the engine from stacking hallucinated unary operators 
(e.g., `sin(sin(sin(X1 - X2)))`) to marginally improve MSE. 

To permanently close this loophole and prepare the engine for the true 100-equation gauntlet, 
two final parameters were implemented:

1. Non-Linear MDL Penalty:
   The flat linear penalty was replaced with an aggressive, non-linear length penalty 
   (`lambda_penalty * active_len * np.log2(active_len + 1.0)`) applied directly to the 
   fully unrolled physical footprint of the array. This effectively enforces a strict 
   Occam's Razor, heavily punishing recursive deep stacking unless it yields an exponential 
   reduction in error.

2. Dynamic Crossover Scheduling:
   The static 80/20 crossover ratio in Level 3 was replaced with a dynamic time-decaying 
   schedule (`min(0.95, 0.20 + 0.75 * (gen / max_generations))`). This forces a high 
   mutation rate (80%) during the earliest generations to explosively map the topology 
   and fill the Parts Bin, then smoothly scales to a 95% crossover rate as the Pareto fronts 
   mature, aggressively exploiting the discovered macros.

**Final Verification:**
The non-linear MDL penalty successfully killed the hallucinations, causing the deeply nested 
structural traps to correctly timeout (returning `None`) instead of reporting massive stacked 
sine waves. The dynamic crossover simultaneously drove `feynman_I_39_1` to an exact solution 
(`3*X1*X2/2`) in just 66 generations (1.8 seconds). 

PRIME 2.0 is fully built, mechanically sound, perfectly constrained, and fully armed for

In a 10-variable problem padded for the JIT evaluator, the base vocabulary explodes 
(~420 possible base combinations for the parts bin). The probability of a purely random

mathematical tree (where the stack pointer exactly equals 1) is astronomically low.

valid equation, `best_mse` remained at `1e9`. The AFPO Pareto fronts were never seeded with 
an initial elite, and therefore, the dynamic crossover mechanism had nothing to crossbreed.

Before PRIME 2.0 can tackle 10+ variable SRBench datasets or whitebox massive latent 
architectures (Layer 2), the initialization mechanics must be upgraded. It requires either 
a syntactically aware generator (e.g., Full/Grow method) to mathematically guarantee valid

**Resolution Experiments:**
To resolve this, two experiments were conducted sequentially:

1. **Experiment 1 (The Loose GP Approach):** The `sp == 1` constraint was removed, allowing

2. **Experiment 2 (The Architect's Approach):** The strict `sp == 1` constraint was reinstated,

   *Result:* Gen 0 seeded the Pareto front flawlessly. The topological crossover fired at 100%
